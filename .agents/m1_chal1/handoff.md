# Handoff Report: Challenger 1 (Milestone 1 — Micro-Index Data Integrity)

## 1. Observation

Adversarial empirical testing was executed against `public/data/hadith/hadiths_micro_index.json` (generated by `scripts/generate_hadiths_micro_index.mjs`).

### Metrics & Contract Checks
- **File Size**: `2,847,219 bytes` (2.72 MB). Requirement: `< 3,000,000 bytes`. **Status: PASS**
- **Total Hadith Tuples**: `50,884`. Requirement: `50,884`. **Status: PASS**
- **Collection Count**: `17` collections in `books` array. **Status: PASS**
- **Grade Dictionary**: `5` grades in `grades` array (`['صحيح', 'حسن', 'ضعيف', 'موضوع', 'مقبول']`). **Status: PASS**
- **Tuple Structure**: Every item has length 5 (`[bIdx, hId, cId, preview, gIdx]`). **Status: PASS**
- **Book Index (`bookIdx`)**: All 50,884 items have integer `bIdx` in `0..16`. **Status: PASS**
- **Hadith ID (`hadithId`)**: All 50,884 items have integer `hId >= 0`. **Status: PASS**
- **Grade Index (`gradeIdx`)**: All 50,884 items have integer `gIdx` in `0..4`. **Status: PASS**

### Defects Identified

#### Defect A: Non-Integer `chapterId` (85 tuples)
- **Observed**: Exactly 85 items in `nasai` (indices 27930 to 28014, hadith IDs 3866 to 3950) contain floating-point `cId` values (e.g. `35.2`).
- **Verbatim Tuples**:
  ```json
  [4, 3866, 35.2, "انبانا عبد الله عن شعبه عن حماد عن ابراهيم ع", 4]
  [4, 3867, 35.2, "انبانا عبد الله عن حماد بن سلمه عن يونس عن ا", 4]
  [4, 3868, 35.2, "انبانا عبد الله عن جرير بن حازم عن حماد هو ا", 4]
  ```
- **Root Cause**: `scripts/generate_hadiths_micro_index.mjs` line 212 uses `h.chapterId ?? 0`. In `nasai.json`, sub-chapters are encoded as decimals (`35.2`), which JS passes through without integer coercion.
- **Contract Violation**: `SCOPE.md` & `PROJECT.md` contract requires `chapterId: number` (integer `0..N`).

#### Defect B: Empty String `textPreview` (125 tuples)
- **Observed**: Exactly 125 items in `malik` (Muwatta Malik, e.g. hadith IDs 35, 237, 239, 332, 386...) have `textPreview: ""`.
- **Verbatim Tuples**:
  ```json
  [6, 35, 2, "", 4]
  [6, 237, 5, "", 4]
  [6, 239, 5, "", 4]
  ```
- **Root Cause**: In HuggingFace `malik.json`, these 125 entries contain empty strings for `h.arabic` (only `h.english` exists). The generator extracts `""` without applying a fallback placeholder (e.g. Arabic book/chapter title or transliteration).
- **Contract Violation**: Requirement states `textPreview` must be a non-empty string of clean normalized Arabic text.

#### Defect C: Unstripped Punctuation and Non-Standard Control Glyphs (22 tuples)
- **Observed**: 22 items contain uncleaned characters:
  1. En-dash `–` (`\u2013`) at start of Bukhari items (e.g. idx 2205, 2353, 2585, 2650, 2652, 3099, 3347, 4542, 4650): `– ولكل جعلنا موالي قال`.
  2. Legacy Private Use Glyph `\uF020` in Bulugh al-Maram (idx 43574): `ولابن عدي \uF020 من وجه اخر`.
  3. Quranic bracket `﴿` (`\uFD3F`) in Bulugh al-Maram (idx 44349): `وهو علي المنبر يقرا ﴿`.
  4. ASCII Question Mark `?` in Bulugh al-Maram (idx 43795, 44074, 44440, 44531): `اكل تمر خيبر هكذا? فقا`.
  5. Stray OCR Latin letters (`g`, `l`, `k`, `+`) in Darimi (idx 38592, 39214, 39280, 39628, 40294, 40339) and Bulugh al-Maram (idx 43341).
- **Root Cause**: `normalizeArabicText()` regex at line 48 in `scripts/generate_hadiths_micro_index.mjs` misses `\u2013`, `\uFD3E-\uFD3F`, `?`, and `\uF000-\uF0FF`.

---

## 2. Logic Chain

1. **Observation**: 85 items in `nasai` have `chapterId = 35.2`.
   - **Reasoning**: Downstream search indices and slice loaders (`fetchBookSlice(bookId, chapterId)`) expect integer chapter identifiers. Decimal chapter IDs can cause cache key mismatches and invalid database indexing.
2. **Observation**: 125 items in `malik` have `textPreview = ""`.
   - **Reasoning**: Searching across Hadiths cannot index or match empty text previews, and the UI will render blank preview cards for these 125 hadiths.
3. **Observation**: 22 items contain control glyphs (`\uF020`), unstripped En-dashes (`\u2013`), and Quranic brackets (`\uFD3F`).
   - **Reasoning**: Normalization is meant to provide canonical, clean search tokens; raw punctuation prefixes interfere with exact prefix matching.

---

## 3. Caveats

- The remaining 50,759 items (99.75%) strictly conform to all indexing, range, and format constraints.
- File size is well within the 3MB ceiling (`2,847,219 bytes` / `2.72 MB`).
- Memory allocation to parse the JSON into memory is low (`8.36 MB` heap), confirming suitability for sub-millisecond client operations.
- The 125 empty Arabic hadiths in `malik.json` originate from upstream dataset omissions.

---

## 4. Conclusion & Verdict

**Verdict**: **`REJECT`** (Fixes required in `scripts/generate_hadiths_micro_index.mjs` before Milestone 1 sign-off).

### Actionable Remediation for Worker:
1. **Sanitize `chapterId`**: In `scripts/generate_hadiths_micro_index.mjs`, convert `h.chapterId` to integer using `Math.floor(Number(h.chapterId) || 0)`.
2. **Handle Empty `arabic` in `malik`**: For hadiths with empty `h.arabic`, provide a fallback Arabic string (e.g. `'حديث في الموطا'` or extracted chapter title) so `textPreview` is never empty.
3. **Expand Normalization Regex**: In `normalizeArabicText()`, add `\u2013` (En-dash), `\uFD3E\uFD3F` (Quranic brackets), `?` (ASCII question mark), and `[\uF000-\uF0FF]` (private use glyphs) to the stripped character set.
4. **Re-run Generator**: Run `node scripts/generate_hadiths_micro_index.mjs` to regenerate `public/data/hadith/hadiths_micro_index.json`.
